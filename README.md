# bigImgPin

**桌面端**的**十亿像素级工业图像**查看、定位与标注工具,面向版图、显微影像一类的工业场景 ——
图像全程留在本机,不依赖浏览器、服务器或联网。把几个 GB 到几十 GB 的整幅图切成瓦片金字塔,
像看地图一样缩放浏览,按坐标精确定位到指定区域,并直接在图上圈画标注。

Tauri 2 + Rust + Vue 3,跨平台桌面(macOS / Windows / Linux)。

## 为什么需要它

举例:一张 **41041 × 49841** 的图,约 **20.5 亿像素**:

- **整图解码装不下。** 按 8 位 RGB 展开约 6 GB,ARGB 约 8 GB —— 还没算解码器自己的中间缓冲。
- **单张纹理超 GPU 上限。** 常见 GPU 单维纹理上限是 8192 或 16384 像素,41041 是后者的 2.5 倍,
  整图作为一张纹理提交会直接失败。
- **常规软件无响应。** 多数看图工具的处理方式是「整图读进内存再显示」,于是长时间卡死、
  爆内存被系统杀掉,或者干脆报「文件过大」。

所以大图不能「打开」,只能**按视野分块、按需加载**。bigImgPin 不试图把整图放进内存,
而是把它变成一张可以漫游的地图。

## 它能做什么

### 浏览

- 打开图片后自动切片并浏览(首次要等,之后命中缓存秒开)
- 拖动平移、滚轮缩放(1.4× 步进),「适应窗口」「1:1」一键到位
- 右下角常驻小地图(导航器),随时知道自己在整图的哪个位置
- 自动网格:按 1-2-5 序列随缩放换挡,左上角标注当前格宽 `网格 N px`
- 状态栏实时显示**光标处的图像坐标**(位数可调,默认整数)、图像尺寸与像素总量、缩放比例、
  当前网格步长、框数量、本次图像的瓦片缓存占用
- 切片过程可随时「取消」

### 坐标小数位

「坐标输入」右上角有个**小数位**选择,**默认 0,也就是全按整数**。

它同时管三件事:屏幕上的读数、新画的框的坐标精度、导出 CSV 的位数。
拖拽时反算出来的 `1234.57` 只是屏幕坐标的副产品,在整数坐标系里既读不出来
也没有意义,所以默认把它收敛掉。拖动时手感会变成「一格一格跳」。

三件事绑在一起是刻意的:分开设就会出现「屏幕上写 1235、文件里存 1234.57、
导出又是 1234.57」,三处对不上,人就没法信任何一处。

改小位数**不会回头改动已有的框** —— 那些框保持原值,谁被拖过谁就吸附过来。
要连已有的一起重算,手动过一遍或重新生成即可。

### 定位

两种方式,都基于**图像像素坐标**:

1. **按 x / y / w / h 定位区域。** 右侧「坐标输入」填 x、y、w、h,生成对应的框。
   还可以填「偏移与系数 k」做一次线性变换再生成:

   ```
   x' = (x + 偏移x) · k
   y' = (y + 偏移y) · k
   w' = w · k
   h' = h · k
   ```

   适合「在一个坐标系里量好尺寸、换到另一个坐标系里标注」的场景。生成前有实时预览,
   结果超出图像范围会给出提示。

2. **跳回框的位置。** 框列表里每个框有「定位」按钮:框能完整放下就平移居中,
   放不下就自动缩放到刚好容纳。在 20 亿像素的图上,这是从一堆框里回到某一个框的
   实用方式。

### 标注

- 画框模式(✛)下拖拽空白处新建框
- **拖框身**整体平移,**拖八个手柄**改尺寸(选中一个框后手柄才出现)
- **双击列表里的某一行**给它起名字,名字会一起写进标注文件和导出的表格
- 每个框自动分配颜色,便于区分
- **撤销 / 重做** —— 工具栏有按钮,键盘更快
- **自动保存**:改动后立刻存到图片旁边,没有「保存」这个动作

选中的框在画布上画得更粗;`Ctrl`/`Cmd` 点多选,选中的可以一起拖动、一起删。

辅助手段:

- **双击**放置一条横向辅助线,**Shift + 双击**放置竖向 —— 用来比对同一 y 或同一 x 上的结构

#### 快捷键

| 键 | 作用 |
|---|---|
| `Ctrl`/`Cmd` + `Z` | 撤销 |
| `Ctrl`/`Cmd` + `Shift` + `Z`、`Ctrl` + `Y` | 重做 |
| `Delete` / `Backspace` | 删除选中的框(可多选) |
| `方向键` | 微调选中的框 1 px |
| `Shift` + `方向键` | 微调 10 px |
| `Esc` | 取消选中 |
| `Ctrl`/`Cmd` + 点击 | 加选 / 减选 |
| 双击 / `Shift` + 双击 | 放置横向 / 竖向辅助线 |

一次拖拽、一段连续的方向键微调、一批删除,在撤销栈里都只占**一步** ——
撤销栈是用来找回「刚才那下」的,不是用来回放鼠标轨迹的。

手柄只在**画框模式**下出现:拖动模式下拖拽是平移画面,画着几个拖不动的方块是骗人。

#### 标注存在哪

存源图旁边,文件名是 `<图名>.bigimgpin.json`(追加而不是替换扩展名 ——
同目录下 `a.tif` 和 `a.png` 是两张不同的图,不能共用一份标注)。
图拷给别人时标注跟着走,也能一起提交进版本库。

同目录不可写时(只读盘、网络盘、程序目录里的样图)自动退回应用数据目录,
状态栏「标注」那一格显示实际位置。

文件里记着这份标注是贴着多大的图存的。对不上(图像尺寸或文件大小变了)会提示,
但仍然照常加载 —— 有时就是要拿旧标注在新图上对照。

### 导出

- **框坐标 → CSV。** 一行一个框(序号、x、y、w、h、名称),可直接进 Excel。
  位数跟着「坐标小数位」那个设置走(默认整数),所以表格里的值和屏幕上的读数一致。
  名字里带逗号或引号时按 CSV 规矩转义 —— 不转义的话一个逗号就会让整行错位。
- **框内图像 → 裁剪图。** 每个框一张,按 `001_x1234_y5678_512x512.png` 命名,
  存到自选目录。部分框压在图像边界上时自动夹取,完全在图外的跳过并如实报出来。

坐标导出上有个**套用逆向变换**的开关:

```
x = x图 / k − 偏移x
y = y图 / k − 偏移y
w = w图 / k
```

也就是回到你当初「按坐标定位」时输入的那套坐标系(和生成框时那条正向变换互逆)。
适合「在图上圈了 20 个位置,把它们的数值交给另一个系统」这种反向流程;
默认不勾,导出的就是图像像素坐标。

裁剪图默认是 PNG。源图是 8 位或 16 位时正常;源图是浮点等格式时自动改用 TIFF ——
实测 PNG 会把 32 位浮点**静默**压成 8 位,而静默丢精度比报错更危险。

| 前端 | Vue 3 + TypeScript + Vite | |
| 瓦片渲染 | OpenSeadragon(canvas drawer) | |
| 叠加层 | 自绘 SVG(屏幕空间) | 线宽恒为 2px,不随缩放变成色块 |

## 关键原理:瓦片金字塔

### 一次切片

`vips dzsave` 把整图按 2 的幂逐级降采样,每一级再切成固定大小的瓦片,产出标准 DZI:

```
image.dzi            # 描述符:格式、瓦片尺寸、原图宽高
image_files/
  ├─ 0/  …           # 1×1,缩略图那一级
  ├─ 1/  …           # 每往下一级,边长翻倍(除不尽向上取整)
  ├─ 2/  …
  └─ …               # 最后一级才是全分辨率
```

索引方向和直觉相反:**0 是最小的一级**,数字越大越清晰。实测一张 6000 × 4000 的图:
`0/` 只有一张 1×1,`1/` 是 2×1,`13/` 才是 6 × 4 = 24 张全分辨率瓦片,整个金字塔 43 张。

仍以这张 41041 × 49841 的图为例:瓦片 1024 px,全分辨率那一层是 41 × 49 = **2009 张**,
整个金字塔共 **2748 个瓦片文件**。前端只按当前视野和缩放级别请求需要的那几十张,
所以**图有多大都不影响交互**——一次视野变化只跟瓦片尺寸和磁盘速度有关。

### 为什么瓦片是 1024,而不是 DZI 惯用的 256

瓦片越大压缩率越高(同一块内容的上下文更多),但解码后占的内存也越大。
1024 是实测折中。作为参照:1024 × 1024 的瓦片解码后是 4 MB,而全分辨率那一层
全部展开要 8 GB —— 所以前端只保留最近用过的 80 张(约 320 MB)。

### 为什么默认 WebP 无损,不用 JPEG 或 PNG

- 比 PNG 小约 **35%**,而逐像素相减最大差值为 **0**(真正无损)
- **不用 JPEG**:目标图是边缘锐利的版图类图像,JPEG 会在每条边产生振铃伪影,
  而那可能被当成真实结构读出来。对一个用来「看结构」的工具,这是不可接受的

### 缓存

切片结果落在 `app_local_data_dir()/tiles/<cache_key>/`:

- `cache_key = hash(路径, 文件大小, mtime, 切片参数)`。切片参数**必须**进 hash,
  否则改了瓦片尺寸或格式会命中旧缓存、拿到尺寸不符的瓦片,表现为图像错位。
- 落盘走 `.tmp-<id>-<pid>/` → 原子 rename,中途崩溃不会留下被误判成「命中」的半成品。
- 命中判定要求 `image.dzi` 和 `image_files/` 同时存在。
- 同一张图第二次打开直接命中,状态栏会标 `(已缓存)`。

### 瓦片怎么送到前端

不用 Tauri 内置的 asset 协议,而是自实现 `bigimgpin://` 自定义协议
(Windows/Android 上是 `http://bigimgpin.localhost`),只暴露缓存根目录,
把 MIME、缓存头、404 语义都握在自己手里 —— 出问题时前端看到的是明确的 HTTP 状态码,
而不是一块没有解释的白。

### 进度

切片期间 `tile-progress` 有两条来源并行:vips 自己报的百分比(`VIPS_PROGRESS=1`,
从 stdout 解析),以及数已落盘瓦片文件的兜底估算。多线程下 vips 的进度可能不平滑,
前端取两者较大值,避免数字回退。

## 运行

**Windows 安装包自带 libvips**(`vips-win64/`,与 exe 同级),装完直接用,不需要另装或配 PATH。

从源码运行、或在 macOS 上,libvips 要自己准备 —— 它是外部二进制,不是链接进来的库:

```bash
brew install vips          # macOS
```

启动时按「随包捆绑 →`BIGIMGPIN_VIPS` 环境变量 → macOS brew 路径 → PATH」的顺序查找;
找不到会直接在界面上给出安装提示。

```bash
git clone https://github.com/Sapphire611/bigImgPin.git
cd bigImgPin
npm install
npm run dev                # 开发(自动起 vite,端口固定 1420)
npm run dev:web            # 只起前端(纯浏览器里没有 Tauri API,invoke 全会失败)
npm run build              # 类型检查 + 打包前端
npx tauri build            # 打包桌面应用
cargo test                 # Rust 单测(在 src-tauri/ 下)
```

可打开的格式:jpg / jpeg / png / tif / tiff / bmp / webp / vips。
libvips 能解的格式远不止这些,选择器里列的是常用几种。

## 项目结构

```
src/
  api/tauri.ts            # 所有 invoke 与事件监听都封在这里,组件只 import 它
  state/useAnnotations.ts # 框 / 辅助线 / 撤销栈,所有标注改动都走它
  osd/coords.ts           # 图像坐标 ↔ 屏幕坐标的唯一出口
  osd/useViewer.ts        # OpenSeadragon 实例与配置
  osd/useAnnotationSvg.ts # 网格 / 辅助线 / 框 / 预览框,一整层屏幕空间 SVG
  components/             # ToolBar / StatusBar / RectPanel
  App.vue                 # 状态与交互编排
src-tauri/src/
  commands.rs             # 切片、缓存、进度、取消
  annotations.rs          # 标注文件的读写(源图旁边的 sidecar)
  export.rs               # 导出:坐标 CSV、框内图像裁剪
  vips.rs                 # vips 定位与 dzsave 调用
  tiles_protocol.rs       # 自定义协议与 URL 前缀的唯一收敛点
  lib.rs                  # 命令注册
```

## 已知限制

- **读不出已有的标注文件时,自动保存会停用**(JSON 损坏、或是更新版本写的)。这时改动不落盘,
  得先手工处理掉那个文件。宁可这样,也不拿一份空标注去覆盖用户唯一的产出物。
- **裁剪图取靠右下角的区域时可能很慢。** `extract_area` 对金字塔 TIFF 是随机访问,
  但源图若是条带式压缩(非金字塔 TIFF、大 JPEG/PNG),就得从头解码到那一行。
  没有为此做「从缓存瓦片拼接」—— 那条路要自己解码、对齐、缝合,不值得。
- 网格步长自动计算,不可手调;切片参数(瓦片尺寸 / 格式)也还没开放到界面。
