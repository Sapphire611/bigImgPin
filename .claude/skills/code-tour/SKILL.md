# 代码走读文档（单文件 HTML）

把一条链路 ——「用户点一下」到「数据落在磁盘上」—— 连同它的代码和理由,做成一份**双击就能离线打开**的网页。

读者画像:能读代码、但不是这套技术栈的人（例:Node 全栈第一次看 Tauri + Rust + 外部 CLI）。
所以文档的一半工作在**翻译**:把陌生的机制挂到读者熟悉的概念上。

## 一、什么时候用

用:用户要「给研发看的说明」「讲清楚数据流向 / 实现原理」「为什么这么设计」。
不用:仓库里 `README.md`（用户手册）和 `CLAUDE.md`（改代码时的规约）已经覆盖的东西 ——
这三份的读者不同,**内容重叠是对的,但别整段互抄**。CLAUDE.md 记「改的时候注意什么」,
这份记「它是怎么跑起来的」,所以这份可以大量贴代码,而 CLAUDE.md 不能。

## 二、先核实事实（不能省的一步）

文档里每一个数字、路径、数据结构,都要能回答「哪来的」。

| 要写的东西 | 从哪拿 |
|---|---|
| 「共 N 级 / M 张 / 多少 MB」 | 磁盘上真数一遍,或用**源码里那段公式**现算,别估 |
| 目录结构、产物长什么样 | 直接 `ls`/`cat` 真实产物,别手画「示意版」 |
| 字段名、默认值、超时 | 读源码常量,连同它上面那段注释一起抄 |
| **第三方库的行为** | 去 `node_modules` / 依赖源码里读,**不许凭记忆** |
| 界面上的一句话 | 从组件里抄原文,别转述 |

第三条值得单说,2026-09-28 差点栽在这:要写「切片金字塔的目录号从哪头数」,
记忆里是「目录 0 = 全分辨率」,而实际是反的。去 `node_modules/openseadragon` 里读了
`getTileUrl` 与 `getLevelScale` 才确认 level 0 = 1×1、最大号才是全分辨率 ——
**同一个事实,去缓存目录 `ls` 一遍也能确认**。凭记忆写这种「方向性」的细节,错了没人能看出来。

反过来,核实过的数字会变成文档的骨架:41041×49841 按 1024 切是 17 级 / 2746 张,
和 README 里实测数过的数对上了 —— 这个对齐本身就是一次验证。

### 能重算的,就别手写

手写进文档的数字只有两种结局:**抄错一个数**,或者**代码改了它不跟着改**。
两种都看不出来 —— 文档不会报错,它只会安静地教错东西。

所以凡是源码里有公式、有常量、有清单能算出来的,就让文档**现算**:
README.html 里那句「17 级 · 共 2,746 张 · 末级 41×49」不是敲进去的,
是照 `vips.rs::expected_tile_count` 的公式在浏览器里现算的 —— 读者改个输入就能看它变,
而数字一旦和源码对不上,页面打开就是错的,不需要谁来发现。

| 别手写 | 改成 |
|---|---|
| 「共 N 张 / M 级 / 多少 MB」 | 源码公式现算,或磁盘上真数一遍 |
| 命令表 | 从 `generate_handler!` / 路由表抄 |
| 事件表与载荷字段 | 从 emit 的那一行抄,不从记忆抄 |
| 类型契约 | 从 `types.ts` 抄（它和 Rust 那边是互为镜像的两半） |
| 版本号 | 从 `package.json` / `Cargo.toml` 读,别写「最新」 |
| 文件路径 | 先在本机确认它真的存在,再写进去（含大小写和 `\` 与 `/`） |

## 三、骨架（10 节,顺序别乱）

| # | 节 | 职责 |
|---|---|---|
| 01 | 谁在跑 | 有几个进程/执行体、边界是什么、代码分布。**顺手给一张「给 XX 背景的对照表」** |
| 02 | 核心概念 | 主链路里最陌生的那个概念,讲它落在磁盘上长什么样 |
| 03 | 全链路 | 泳道序列图 + 逐跳代码（**这份文档的主菜**） |
| 04-08 | 各机制 | 每个机制一节,固定三段式:解决什么问题 → 关键代码 → 不这么写会怎样 |
| 09 | 看着像 bug 的故意设计 | 一张表,「看着像 X / 其实是 Y」。**被引用最多的一节** |
| 10 | 速查与验证 | 命令表 / 事件表 / 文件表 / 怎么验证改动 |

主链路的写法:
- 先用**泳道序列图**给全景（3–4 条泳道:前端 / 边界 / 后端 / 外部系统）,每条箭头 = 一次跨边界调用;
- 再逐跳展开成 hop 卡片,标题写「谁做了什么」而不是函数名,右上角标 `文件:行号`,
  正文写「为什么放在这一层」,代码贴真片段（可节选,**一个字都别改**）;
- 跳数控制在 8–14。少于 8 说明还没讲透,多于 14 该拆成两节。

冷热路径要分开标:第一次打开（要切几分钟）和命中缓存（秒开）是两条路,
读者最容易被这个绊住。

## 四、配色与排版

**从项目自己的设计令牌里抄**,别自己发明（本项目就是 `src/styles.css` 的 `:root`）。
没有令牌就从**题材**里找理由:配色得有一个能说出口的来源,不能是「深色 + 紫色渐变」那种
放在任何项目上都成立的默认皮肤 —— 那样读者一眼就看出是生成的。

三条落到实处的规则:
1. **界面零彩度**:框架、边框、正文全中性灰。理由是本项目那条「界面里一点色偏都会让人看偏图」,
   文档同理 —— 读者盯着的是代码。
2. **颜色只出现在数据上**:在这里数据就是代码 token。三种就够 ——
   关键字、字符串、注释。别给类型名/数字/函数名各来一个颜色。
3. **单文件、离线**:不引 CDN、不引字体、不引高亮库（几十行正则就够,见模板）。
   双击能开,和这个项目本身的立场一致。

机制（令牌、目录栏、泳道图、hop 卡片、高亮器、可视化块）都已经在
`template.html` 里了 —— **复制它,不要重新写一遍**。模板文件头写着要改哪四处。

## 五、验证（必做,而且不等于截图）

```bash
# 1) playwright 拦 file://，起个静态服务（在仓库根跑）
node -e "const h=require('http'),f=require('fs'),p=require('path');h.createServer((q,s)=>{const g=p.join(process.cwd(),decodeURIComponent(q.url.split('?')[0]));f.readFile(g,(e,b)=>{if(e){s.writeHead(404);s.end();return}s.writeHead(200,{'content-type':'text/html; charset=utf-8'});s.end(b)})}).listen(8899)"
```

2) 打开后**先看 console**:0 错误才算过。一个 JS 报错会让整页脚本停摆 ——
样式还在、高亮/图表/目录高亮全没了,截图上看不出来。

3) 断言读 DOM（比截图可靠,本机 125% DPI 截图本来就不可信）:

| 断言 | 期望 |
|---|---|
| `pre > code span` 数量 | > 0（高亮器真的跑了） |
| 各 `figure` 的 textContent | 含 `Vec<u8>`、`&mut x` 这类真字符（转义没漏） |
| 空 `.seq__card` 数量 | 0（占位格没用错 class） |
| `documentElement.scrollWidth - clientWidth` | 0（没有横向溢出） |
| 现算的数字 | 与磁盘/源码对齐（例:17 级 · 2746 张 · 末级 41×49） |
| `#toc a.on` | 滚到某一节后恰好 1 个 |

4) 自绘的块（泳道图、canvas 可视化）**单独截图看一眼**:用能看图的东西看
（本项目有 `deepseek-eyes` skill）。要问具体问题:「标签有没有压线」「方块糊没糊」「深浅两套对比度够不够」,
不要问「好看吗」。

5) 主题:默认跟随系统,**深浅两套都要看一遍**（headless 浏览器默认是浅色,别只验到一套）。

## 六、踩过的坑

1. **相邻两个 `(function(){})()` 之间必须有分号。** 漏了会被解析成函数调用,
   报 `intermediate value is not a function` —— 而且只在第二个块上炸,
   表现是「页面能打开、样式正常、但高亮/图/目录全空」。所以第三节那条「先看 console」是硬的。
2. **代码块里的 `<` 和 `&` 必须写成 `&lt;` `&amp;`。** `Vec<u8>` 会被 HTML 解析器当成未知标签
   **整段吞掉**（不是显示成乱码,是消失）。高亮器读的是 `textContent`,所以渲染后仍然是真字符,
   不用担心高亮失效。
3. **高亮器要单遍扫描,注释分支放最前。** 换成「先替换字符串、再找注释」两遍,
   `"http://…"` 里的 `//` 就会被当成注释头,后面半行都变色。
4. **泳道图的空占位格要用空 `<div>`**,别用 `<div class="seq__card"></div>` —— 后者会渲染成一排空方框。
5. **箭头标签放在线的中点上**,不是容器中点上:模板里是
   `left: calc(50% + (var(--x1) - var(--x2)) / 2)`,手写 `left: 50%` 会让标签飘到旁边的空泳道里。
6. **ASCII 示意图加 `data-plain` 跳过高亮**,否则图里的 `vips`、`git`、`node` 这些词会被染成关键字色。
7. **HTML 注释里不解析实体**:注释里写的 `&lt;` 就是四个字符。给读者看的提示要写原字符（`<`）。
   另外注释里不能再嵌 `<!--`,也不能出现 `-->`。
8. **`file://` 被 playwright 拦**,一律起 http 服务验（见第五节）。
9. **大文件一次写完**,别用几十个 Edit 拼 —— 会丢掉全局一致性。写完复查三样:
   转义、IIFE 分号、空占位格。
